# Default source preferences by domain

Starting points only. `LOCAL.md` adds to or replaces these. Pick the domain that matches the task; load only that section.

## Web and app development
- Official docs of the framework or platform, MDN, the project's own changelog and migration guides.
- Prefer maintainer blog posts and RFCs over third-party tutorials for API behaviour.

## Backend, data and infrastructure
- Vendor documentation and the engineering blogs of teams running the technology at scale.
- For anything touching saved data, money or auth: also read one postmortem or security advisory.

## Game development
- Engine documentation first (Unity, Unreal, Godot, Roblox Creator Docs), then the engine's official forum.
- Postmortems and conference talks for design and performance questions.
- Check API deprecations: engine APIs change faster than tutorials.

## 3D and art tools
- The tool's official manual (for Blender, the Python API docs and manual), then respected tutorial authors.

## Research and data work
- Original papers or datasets, then the library's documentation. Note the version used.

## Anything else
- Official documentation, then postmortems, then well-maintained open-source projects that solve the same problem.
